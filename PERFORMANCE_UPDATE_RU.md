# Blocks Menu — Performance update 01

## Что оптимизировано

1. **Поиск производственных станков (`RecipeBenchFinder`)**
   - Раньше список зданий колонии просматривался отдельно для каждого `RecipeDef`.
   - Теперь один проход по станкам карты строит индекс `RecipeDef -> List<Building>`.
   - Индекс живёт 300 игровых тиков, как и прежний кэш.

2. **Подсчёт запасов ингредиентов (`GameComponent_BlocksMenuQueue`)**
   - Раньше каждый новый `ThingDef` ингредиента вызывал полный проход по `map.listerThings.AllThings`.
   - Теперь за один проход агрегируются количества всех типов предметов, находящихся в складских зонах/хранилищах, а также в инвентарях свободных колонистов.
   - Результаты кэшируются на 300 игровых тиков. Правила включения предметов сохранены: складские зоны, штатное хранение/полки и инвентарь свободных колонистов.
   - Убрана повторная проверка всех ячеек складских зон для каждого предмета: ячейки собираются один раз в HashSet.

3. **Объединённый список станков в активной очереди**
   - Результат объединения и сортировки станков для выбранной папки теперь кэшируется по карте, папке и версии кэша рецептов.
   - Это убирает повторное создание HashSet/списка и сортировку на каждом GUI repaint.

4. **Каталог брони**
   - Списки предметов по группам покрытия тела строятся один раз при формировании кэша Def.
   - Повторные обходы всех предметов брони и повторное чтение BodyPartGroup при каждом кадре устранены.

5. **Каталог оружия**
   - Категории оружия возвращают готовые кэшированные списки вместо создания новых копий при каждом отображении.

## Что не менялось

- Логика создания и выполнения Bills.
- Сохранение и загрузка заказов и папок.
- Сами производственные станки и их интерфейс.
- Правила выбора рецептов, режимы повторения и назначение заказов.
- Критерии учёта складов и инвентарей (перенесены в единый проход).

## Проверка

Это обновление исходников. В среде подготовки нет компилятора .NET Framework/RimWorld, поэтому DLL не пересобиралась и игровой тест TPS не выполнялся. После установки нужно выполнить `Build-Mod-Force-Rebuild.bat`, затем проверить TPS с открытым и закрытым Blocks Menu.

## Что прислать для следующего этапа

- Результат сборки.
- TPS до/после в одной и той же сохранённой игре, на одинаковой скорости и при одинаковом числе колонистов/животных.
- Уточнение: TPS падает постоянно или преимущественно при открытом Blocks Menu.


## Единое правило доступности рецептов (обновление)

Во всех пяти каталогах — «Производство», «Спецодежда», «Одежда», «Броня» и «Оружие» — показываются только рецепты/предметы, которые можно изготовить хотя бы на одном завершённом станке, размещённом на текущей карте. Станок должен предоставлять `IBillGiver`, штатный `BillStack` и рецепт в `ThingDef.AllRecipes`. Проверки питания, топлива, выключателя и текущей занятости не выполняются: неработающий из-за электричества или топлива станок всё равно делает рецепт видимым.

Для снижения нагрузки строится общий индекс рецептов и их продуктов за один обход станков карты. Индекс обновляется при смене карты и каждые 300 игровых тиков. Подробности — в `RECIPE_AVAILABILITY_RULE_RU.md`.
