# Blocks Menu — RimWorld 1.6

## Назначение

Blocks Menu — единое окно для просмотра производственных рецептов, организации их по папкам и управления заказами колонии. Каталоги предметов автоматически анализируют загруженные игровые определения, включая определения из установленных модов.

## Модули

- **Производство** — каталог рецептов, поиск, папки, создание и просмотр производственных заказов.
- **Активные заказы** — общий список оригинальных Bills с разных станков. Заказы остаются привязаны к исходным `BillStack` и станкам.
- **Папки** — пользовательские категории рецептов, автоматическое наполнение по выбранным станкам, ручное добавление и исключение рецептов.
- **Спецодежда** — каталог профессиональной экипировки и инструментов с анализом игровых характеристик.
- **Одежда** — каталог одежды с фильтрами и панелью характеристик.

## Структура проекта

- `Source/MainTabWindow_CraftingMenu.cs` — главное окно, производственная очередь, папки, редакторы и сохранение данных.
- `Source/BillInterfaceHarmonyPatch.cs` — Harmony-интеграция, ограниченная отображением списка Blocks Menu.
- `Source/RecipeBenchFinder.cs` — поиск совместимых производственных станков.
- `Source/ProductionOrderMode.cs` — режимы общего производственного заказа.
- `Lib/` — библиотеки RimWorld, Unity и Harmony, необходимые для компиляции.
- `1.6/Defs/` — определение кнопки главного меню.
- `Languages/` — используемые ключи локализации.

## Сборка в Windows

Требуется .NET SDK 8 или новее. Откройте папку мода и запустите один из файлов:

- `Build-Mod.bat` — обычная сборка Release.
- `Build-Mod-Force-Rebuild.bat` — принудительная полная пересборка.

Результат: `1.6/Assemblies/BlocksMenu.dll`.

## Установка

Папка мода должна находиться в `RimWorld/Mods/BlocksMenu`. После сборки проверьте наличие `1.6/Assemblies/BlocksMenu.dll`.

## Технические границы

- Мод работает с оригинальными игровыми `Bill` и `BillStack`, не заменяя производственную систему RimWorld.
- Harmony-патчи списка заказов должны действовать только во время отрисовки очереди Blocks Menu; обычные интерфейсы станков не должны изменяться.
- Классификация предметов строится по загруженным Defs и доступным игровым свойствам. Нестандартные предметы модов могут требовать дополнительных правил классификации.
- Исходники необходимо собрать и проверить в установленной RimWorld 1.6. Наличие исходников само по себе не означает, что DLL уже собрана или протестирована.
